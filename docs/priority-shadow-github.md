# GitHub로 받는 주문 없는 통합 신호 확인

이 브랜치는 5분봉9.55배·15분봉5배 후보 신호를 실제 데이터로 확인하는 관찰 도구다. 실거래 통합 제어기를 활성화하지 않는다. 기존 main.py, 서비스, .env, 계좌, 주문 설정을 변경하지 않는다.

## 실행

운영 저장소에서 이 브랜치를 fetch한 뒤 별도 worktree를 만든다. 기존 저장소에서 checkout, reset, pull하거나 수정 파일을 덮어쓸 필요가 없다.

별도 worktree 안에서 다음을 실행한다.

```bash
bash scripts/run_priority_shadow.sh
```

서버의 기존 Python 환경을 재사용한다. 다른 환경에서는 PRIORITY_PYTHON으로 실행 파일을 지정한다. 다음 5분봉 마감부터 세 경계를 관찰하고 종료하며, 최대 약15분 걸린다. 세 경계 중 하나는 15분봉 마감이다. 결과는 표준 출력과 사용자 상태 디렉터리의 SQLite에 기록한다.

- SHADOW_SIGNALS_ONLY: 공개 API와 기존 모바일 중계를 사용하는 후보 신호 관찰.
- OBSERVED: 필요한 데이터가 모두 갖춰져 판단을 완료함. 매매 실행이나 체결을 의미하지 않는다.
- BLOCKED: 4개 거래소 결측, 시각 불일치, 조회 지연 등으로 해당 경계를 판단하지 못함.

두 시간봉이 같은 시각에 마감되면 모두 검증해야 한다. 30초를 넘겨 도착한 데이터로 신호를 되살리지 않는다. 중복 경계는 SQLite 기본키로 억제한다. 관찰 도구에는 보유 포지션·매매 이력에 따른 쿨다운이 없으므로 raw 후보만 출력한다.

통합용 15분봉은 거래량 SMA40, N봉 상한6.3, RSI 과매도 상한42.0, 재진입5봉이다. 현재 서버의 SMA41·6.1·41.5·7봉과 다르다. 명시적 프로필을 사용하며 기존 서버 설정을 바꾸지는 않는다.

## 검증 범위

이번 브랜치의 새 신호 테스트는 18개다. 확정 시각, 미래 봉 제외, 네 거래소 결측, 잘못된 가격·거래량, 환경변수와 설정 분리, 정상 신호 생성, 이력 기반 쿨다운, 데이터 재시도 및 재시작 중복 억제를 검사한다.

```bash
python -m pytest tests/test_priority_signals.py -q
```

앞서 별도 로컬 후보에서 수행한 123개 통합 테스트 전체를 이 관찰 전용 브랜치의 CI 결과로 간주하면 안 된다. 실거래 제어기·스캐너 교체·배포·활성화는 이 변경에 포함하지 않는다. 운영 서버에서의 공개 API/모바일 릴레이 수신 결과는 실행 후 확인해야 한다.
