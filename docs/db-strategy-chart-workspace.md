# DB 전략 차트

앱 상단의 **DB 선택 · 캔들 차트**에서 열 수 있습니다. 저장된 DB가 없어도
차트 화면의 **DB 관리 → DB 파일 불러오기**로 SQLite 파일을 앱에 저장합니다.
기존 다운로드 기능도 유지합니다.

## 사용 순서

1. DB 관리에서 파일을 불러오거나 저장된 DB를 선택합니다.
2. 시장에서 **bitget / 원하는 심볼 / 주기**를 선택합니다.
3. **전략 적용**에서 현재 전략, JSON 붙여넣기/파일 또는 제공된 Pine v19 수치를 선택합니다.
4. 선택 DB 전체 기간으로 계산한다는 안내를 확인하고 적용합니다.
5. 캔들을 터치하면 해당 봉의 진단이 표시됩니다. **진단**으로 상세 수치를 확인합니다.
6. **거래**에서 진입·청산 UTC, 가격, 최초 고정 TP/SL, 순손익과 사유를 확인합니다.
   거래 행을 누르면 진입 봉이나 청산 봉으로 이동합니다.

결과와 전략은 DB별로 저장됩니다. **결과**에서 과거 실행을 선택할 수 있습니다.
계산 중 **중지**를 누르거나 화면을 닫으면 취소를 요청합니다.
실행 중인 백테스트가 있으면 DB 관리와 새 전략 적용을 차단합니다.

## 저장과 삭제

- 외부 저장은 SQLite backup API를 사용해 WAL의 커밋 데이터까지 포함합니다.
- 가져온 파일은 이름 뒤에 고유 ID를 붙여 기존 DB를 덮어쓰지 않습니다.
- 삭제는 복구 가능한 휴지통 이동이며, **마지막 삭제 복구**로 되돌릴 수 있습니다.
- **휴지통 비우기** 확인 후 실제 파일을 제거해 저장 공간을 확보합니다.
- 원본 OHLCV DB는 전략 계산 중 읽기 전용입니다.

## 진단의 의미

진단은 독립적으로 재구현한 Pine 신호가 아닌 실제 Vector Engine의 이벤트 관측입니다.
진입 판단 전 쿨다운 계산, 다음 봉 시가/신호봉 종가 체결, 같은 봉 청산 후 재진입
순서를 그대로 관찰합니다. 기록을 켜도 기존 체결·비용·성과가 변하지 않는 회귀 테스트가 있습니다.

거래량, 거래소별 정규화 배수, RSI, ADX, N봉 차단, 시간·쿨다운·연속봉 조건,
신호·실제 진입, 보유 포지션과 고정 TP/SL을 표시합니다.
워밍업 또는 계좌 청산 후의 미계산 구간은 신호가 없는 것으로 오인하지 않도록 구분합니다.
TP/SL 동시 터치 시 앱의 우선순위는 계좌 청산 → SL → TP입니다.
이 결과는 실거래 체결 내역이 아닙니다.

제공된 v19 프리셋은 BTC 15m, 거래량 SMA 41, 6.4배, 8.9배 진입,
15배 노출 한도, 신호봉 종가, 복리, 편도 수수료 0.02%와 슬리피지 0.01%입니다.
기간은 JSON 원본 기간 대신 선택 DB 전체 기간을 사용한다는 안내를 보여줍니다.
거래소 원시 데이터와 봉내 체결 가정 차이로 TradingView 결과와 동일함을 보장하지 않습니다.

## 검증과 제한

- 진단은 별도 .audit SQLite 파일에 timestamp 인덱스로 저장하고 화면 구간만 읽습니다.
- 캔들은 최대 600봉, 거래 표는 페이지당 200개로 표시합니다.
- DB가 변경되면 기존 진단과 거래 오버레이를 무효화하고 재적용을 요구합니다.
- 4거래소 누락/데이터 오류가 있으면 백테스트 오류를 표시하며 부분 결과는 남기지 않습니다.
- Android 실제 단말의 렌더링·터치 성능은 APK 설치 후 확인이 필요합니다.
